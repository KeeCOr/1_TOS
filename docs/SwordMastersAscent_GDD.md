# SwordMastersAscent

## 2026-09-28 전투 턴 규칙과 정보 공개 원칙

**턴 구조:** `적 의도 확인 → 무료 이동 0~1회 → 주 행동 1회 → 판정·피드백 → 다음 턴 보너스 확인`.

- 이동은 주 행동을 소비하지 않는다. 플레이어는 매 턴 이동 뒤 공격·방어·마법·아이템 중 하나를 실행할 수 있다.
- 방어는 `세로 막기`와 `가로 막기` 두 종류이며, 둘 다 들어오는 공격 피해를 50% 줄인다. 방어 방향의 차별 규칙은 MVP 이후 후보로 둔다.
- `perfect` 판정이면서 속도 또는 힘 주사위 합계 차이가 4 이상이면 다음 턴에 `주사위 +1` 또는 `추가 행동 1회`가 같은 확률로 발생한다.
- 추가 행동은 적의 대응 없이 주 행동만 한 번 더 수행한다. 이동과 추가 보상의 연쇄 획득은 막아 폭주를 제한한다.
- 적은 이름, 정확한 HP·MP, 능력치 수치를 공개하지 않는다. 체력·자원 막대, 적 의도, 같은 행 여부, 공격 가능 여부처럼 결정을 돕는 상태만 공개한다.
- 상단 거리 용어 대신 `현재 공격 가능`, `공격 사거리 밖`, `다른 행 — 공격 불가`를 사용한다. 이동 문구는 `적에게 접근`, `거리 확보`, `윗줄/아랫줄로 이동`으로 통일한다.
- 전술 콘솔은 행동 선택을 가장 넓게 배치하고, 오른쪽은 적 의도·전투 기록·실제 존재하는 상세 정보만 표시한다. 장식용 임시 카드와 빈 영역은 두지 않는다.
- 구현 근거: `src/components/SwordmastersAscent.tsx`, `src/lib/gameData.ts`, `src/lib/defenseRules.cjs`, `src/lib/momentumRules.cjs`.
- 검증: 2026-09-28 자동 테스트 28/28 및 프로덕션 빌드 통과. 실제 화면 배율과 보너스 체감 빈도는 미검증이다.

## 2026-09-23 적 의도 기반 위험 판정

- 전투 HUD의 위험도는 이제 거리만 보지 않고 적의 주 행동, 예상 세부 행동, 같은 행 여부, 거리, 무기 사거리를 함께 판정한다.
- 방어 중인 적은 가까워도 낮은 위험으로 표시하고, 전진 압박은 다음 턴 거리 변화, 마법·아이템은 거리와 행을 넘을 수 있는 원거리 위협으로 설명한다.
- 공격 의도는 다른 행, 사거리 밖, 사거리 안, 근접을 구분한다. 특정 정답 행동을 추천하지 않고 플레이어가 확인할 변수와 위험 원인만 제공한다.
- 근거: `src/lib/tacticalRisk.cjs`, `tests/tactical-risk.test.cjs`, `src/components/SwordmastersAscent.tsx`.
- 검증: 2026-09-23 `npm test` 24/24 통과, `npm run build` 통과. 복수 lockfile workspace root 경고는 유지된다.
- 미검증: 실제 첫 3개 층에서 모든 의도 조합의 시각적 겹침과 판단 도움 정도.

## 2026-09-21 확정 핵심 방향

**한 줄 정의:** 적의 의도를 예측하고 거리·공격·방어 전술을 선택해 한 명의 검사를 최고층까지 성장시키는 1:1 로그라이트.

**코어 루프:** `적 의도 확인 → 전술 선택 → 1:1 판정 → 결과 해석 → 성장 보상 → 다음 층 → 개인 최고 기록 갱신`.

- 다수전이나 일반 액션 반복보다 한 적과의 심리전, 제한된 자원, 빌드 누적을 우선한다.
- UI는 현재 층, 개인 최고층, 이번 검사의 성장, 다음 기록 목표를 시작·전투·사망 화면에서 연결한다.
- 위험과 예상 결과는 보여주되 정답 행동을 추천하지 않으며, 전투 후 선택의 결과를 설명한다.
- 출시 기준은 첫 3개 층 안에 예측·전술·성장 차이·최고층 재도전 동기가 모두 체감되는 것이다.

### 전투 기록 진행 HUD — 2026-09-21 구현

- 목표: 전투 중 현재 도전이 개인 최고 기록에서 얼마나 떨어졌는지 계산 없이 읽게 한다.
- 예시 화면: `docs/design-references/2026-09-21-combat-record-gap-hud.png` (목표 상태를 보여주는 콘셉트 이미지이며 실제 플레이 캡처가 아님)
- 레이아웃: 전투 상단의 플레이어 정보 영역 첫 줄에 `현재`, `최고`, `기록 진행`을 연속 배치한다.
- 재사용 컴포넌트: 기존 `StatusPill`을 사용하며 `getRecordProgressStatus`가 상태 문구와 톤을 결정한다.
- 데이터: `floor`, `highScore`, 두 값의 차이만 사용하고 별도 저장 형식은 추가하지 않는다.
- 상태: 첫 기록 도전, 기록까지 N층, 기록 동률, 신기록 +N층을 구분한다. 읽기 전용 표시이므로 로딩·오류 상호작용은 없고 좁은 폭에서는 기존 flex-wrap으로 다음 줄에 배치한다.
- 접근성: 색만으로 상태를 구분하지 않고 각 상태를 실제 텍스트로 표기한다.
